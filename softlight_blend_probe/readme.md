# softlight_blend_probe

柔光混合（W3C Soft Light）用于红外/可见光融合的初步验证实验。作为零参数基线，与 Text-IF text_ratio=T5 的融合结果做同图对比，回答一个问题：不学习的 PS 混合模式能走多远？

## 1. 动机

### 1.1 研究语境：为什么要测一个零参数基线

Text-IF 这类学习方法在融合指标上已经很强，但它的融合权重是纯学出来的黑箱——我们不知道其中有多少"功劳"来自可以显式表达的图像处理先验。把 PS 混合模式（几百年摄影/修图实践沉淀的固定映射）作为零参数基线在同图上与学习方法对比，可以回答两个问题：

1. **差距结构**：学习方法的优势集中在哪些指标上？是全面碾压，还是只在特定维度（如信息传递/边缘保持）有本质优势？
2. **先验价值**：某个混合模式的语义（如"亮处提亮、保底图基调"）若与融合任务契合，就值得作为**网络内的可微融合算子**——网络只需学回它欠缺的部分，而不是从零学整个融合。

### 1.2 为什么选柔光

Photoshop 中"柔光"的经典用法是：**保底图基调，用 blend 层做明暗修饰**——base 层的结构与色调不被替换，blend 层亮处轻微提亮 base、暗处轻微压暗，且修饰强度随 blend 偏离中灰的程度平滑变化（中灰 = 不动）。

这与红外/可见光融合的直觉高度契合：

- **VI 保色彩/结构**：以 vi 为 base，自然保住可见光的彩色纹理基调；
- **IR 提亮热目标**：以 ir 为 blend，红外亮目标（行人等）恰好落在"亮处提亮"的一侧，且 IR 越亮修饰越强。

它全程零参数、逐像素、分段连续（可微），如果性能尚可，就有资格进入网络。本探针用小规模抽样实验检验这一点——**结论是否定的**（见 §4，以及后续 `luminosity_screen_probe` 对"滤色"的修正尝试）。

## 2. 原理

### 2.1 W3C 柔光公式

`softlight_blend_probe/probe_softlight.py` 中的 `softlight(base, blend)` 实现 W3C compositing 规范的柔光：

```text
out = b + (2a − 1) · (D(b) − b)

D(b) = ((16b − 12)·b + 4)·b    若 b ≤ 0.25
D(b) = √b                      若 b > 0.25
```

其中 b = base、a = blend，均取值 [0,1]，逐像素计算。

### 2.2 关键数学性质（决定了实验结局）

**(P1) 中灰恒等**：a = 0.5 时 2a−1 = 0，输出 ≡ base。blend 的亮度单独决定"增/减"方向，base 的色调始终不被替换——这是"保基调"语义的来源。

**(P2) 修饰幅度有硬上界 0.25**（本实验最重要的性质）：修饰量 |out − b| = |2a−1|·|D(b)−b| ≤ |D(b)−b|，而

- b ≤ 0.25 支路：D(b)−b = 16b³−12b²+3b，导数 3(4b−1)² ≥ 0，单调增，在 b=0.25 处取最大值 **0.25**；
- b > 0.25 支路：D(b)−b = √b−b，单调减，在 b=0.25 处同样为 **0.25**，向 b=1 衰减到 0。

即**全强度柔光（a=1）对任何像素的最大改变量不超过动态范围的 25%**，且越亮的 base 区域能被改变的幅度越小（b=1 处完全不可改变）。叠加不透明度后上界进一步缩小：实验最优配置 α=0.6 下，逐像素修饰 ≤ 0.15。这从数学上解释了为什么柔光"对比度指标能赢（SD 拉升）但热目标注入不充分"——它是刻意的温和修饰工具，不是信息注入工具。这一观察直接催生了下一个探针（滤色 + 高光蒙版，见 `luminosity_screen_probe/readme.md`）。

**(P3) 分段连续**：两支路在 b=0.25 处均等于 0.5，D(b) 一阶连续（有单测钉死），无跳变伪影来源。

**(P4) 单调性**：out 随 a、随 b 均单调不减——不会翻转明暗关系。

### 2.3 不透明度 α

`softlight_blend(base, blend, alpha)` 在混合后做不透明度插值：

```text
out = (1−α)·base + α·softlight(base, blend)
```

α 控制柔光强度，α=0 退化为 base 本身。实验扫 α ∈ {0.6, 0.8, 1.0}。

### 2.4 两种层序语义

`fuse(ir, vi, order, alpha)`：

| order | base | blend | 语义 |
| --- | --- | --- | --- |
| `ir_on_vi` | vi（彩色） | ir（灰度广播到 3 通道） | VI 保基调，IR 做明暗修饰（契合直觉的用法） |
| `vi_on_ir` | ir（灰度复制 3 通道） | vi | IR 保基调，VI 做修饰（对照组） |

### 2.5 与 PS 实际实现的差异

Photoshop 实际采用的是 **Pegtop 近似**（D(b) = b²，全域单一多项式），并非 W3C 分段式。两者在中灰 blend 附近行为一致，主要差别在 base 极暗区（b < 0.25）。本实验统一用 W3C 闭式解，复现时注意与 PS 截图的细微差别来源即在此。（P2 的 0.25 上界对 Pegtop 版同样近似成立，不影响结论。）

## 3. 验证设计

- **抽样**：每数据集从 T5 生成目录（`sweeps/out/text_ratio_T5/gen/{ds}/fused`，按文件名排序）取前 3 张：MSRS 00055D/00091D/00095D + TNO TNO_0023/TNO_0024/TNO_0051，共 6 张。MSRS 的 vi 是彩色、TNO 的 vi 是灰度，构成"保色彩动机成立/不成立"的两种场景。
- **配置网格**：2 层序 × α ∈ {0.6, 0.8, 1.0}，共 6 个柔光配置 + T5 基线。
- **图件**：每图输出 `{name}_grid.png`（6 配置网格，挑参数用）与 `{name}_compare.png`（IR | VI | 柔光最优配置 | T5 四联对比）。
- **指标口径**：复用 `metric/Metric_torch.py` 的 10 个指标（EN/MI/SF/AG/SD/VIF/SSIM/Qabf/Nabf/SCD），灰度转换与 `evaluate_experiment_metrics.py` 一致（PIL convert('L')），且**与 T5 输出同图同尺寸**计算——T5 推理管线会把输入 resize 到 16 的倍数（TNO 381×461 → 368×448），因此 `load_pair_t5` 在算指标前把 ir/vi 双线性对齐到 T5 输出尺寸，否则形状不一致。
- **选优规则**（`select_best_config`）：每个 higher-better 指标（除 Nabf 外全部）在配置间做逐图平均、按名次打分（rank 1 得 N−1 分 … rank N 得 0 分），Nabf 按 lower-better 排序，总分最高的配置胜出。
- **公平性**：所有指标对 T5 与柔光在**同一张图、同一尺寸、同一灰度化口径**下计算，不与 T5 全量 evaluation_summary 直接比（那是全测试集均值）。

结论模式非常清晰：**柔光唯一稳定赢的是 SD（6/6 全胜，且 TNO 上 +16~+18 大幅领先），唯一稳定输的是 SSIM（0/6，MSRS 上 −0.20~−0.25）**。其余指标互有胜负但输多赢少。这与 §2.2 的数学分析完全吻合：柔光能拉开明暗（SD↑）但注入的信息量受 0.25 上界约束，同时逐像素修饰偏离了源图结构（SSIM↓）。

### 4.3 逐数据集分解（总体均值掩盖的两个事实）

**MSRS（彩色 VI，"保色彩"动机成立的场景）：**

```text
method                        EN     MI     SF     AG     SD     VIF    SSIM   Qabf   Nabf   SCD
T5                          7.374  5.498  17.321  5.621  68.498  1.018  0.954  0.759  0.011  1.714
softlight/ir_on_vi/0.6      6.973  5.416  19.090  5.769  74.075  0.881  0.792  0.690  0.030  1.250
softlight/vi_on_ir/0.6      5.062  3.250   7.104  2.048  20.023  0.553  0.604  0.141  0.009  1.132
```

- ir_on_vi 在彩色场景确实兑现了"VI 保基调"：SF/AG/SD 小幅超过 T5；但 VIF（0.88 vs 1.02）、SSIM（0.79 vs 0.95）、SCD（1.25 vs 1.71）明显落后——**学习方法从彩色 VI 里传递出的信息，柔光的温和修饰接不住**。
- vi_on_ir 在彩色场景是灾难（SD 仅 20）：把彩色 vi 打到灰度 ir 上等于用低对比度底图压制 vi 的全部纹理与色彩。

**TNO（灰度 VI，"保色彩"动机不成立的场景）：**

```text
method                        EN     MI     SF     AG     SD     VIF    SSIM   Qabf   Nabf   SCD
T5                          6.527  3.724   3.861  1.637  42.293  1.249  1.029  0.588  0.014  1.443
softlight/ir_on_vi/0.6      5.774  3.771   3.157  1.171  54.137  1.170  0.921  0.450  0.005  1.810
softlight/vi_on_ir/0.6      6.392  4.524   3.268  1.425  24.859  1.305  1.005  0.572  0.003  1.242
```

**事实一（层序偏好翻转）**：TNO 上 vi_on_ir 反而在 MI（4.52 vs 3.72）、VIF（1.31 vs 1.25）、Qabf（0.572 vs 0.588 接近）、Nabf（0.003 vs 0.014）上胜过 T5——灰度场景下 IR 亮度信息量相对更足，以 IR 为 base 反而保住了更多信息。总体均值中"ir_on_vi 全面最优"的印象主要由 MSRS（数值量级大）贡献，**层序选择是数据集相关的**。

**事实二（ir_on_vi 在 TNO 的两个例外亮点）**：SD（54.1 vs 42.3）与 SCD（1.81 vs 1.44）大幅反超 T5——灰度场景下"亮处提亮"对对比度的拉升更有效（TNO 本身对比度低，拉升空间大）。

### 4.4 参数趋势

- **层序 >> α**：层序间差距（SD 74 vs 20）远大于 α 间差距（SD 74.1 vs 78.3）；α 增大只是在既定层序上加强修饰幅度，且单调损害 MSRS 的 MI/SSIM（信息被更强的修饰扭曲）。
- **定性观察**：ir_on_vi 顶行偏 IR 暗调、vi_on_ir 底行偏 VI 亮调（网格图行间差异一目了然）；柔光结果亮度自然、接近"VI 略增强"的外观。

### 4.5 总体判断

柔光作为**零参数**混合能获得不错的外观与高对比度（SD 稳定 6/6 全胜），但保真类/信息传递类指标（SSIM 0/6、VIF 1/6）与学习方法差距是本质性的——根源是 §2.2 的 **0.25 修饰上界**：它是"修饰工具"而非"注入工具"。结论：

1. **不是端到端融合方法的替代品**，也不适合作为论文对比表中的基线（会被学习方法碾压保真类指标）；
2. 更有价值的用法是作为**融合网络中的一种先验混合算子**：在网络内用柔光语义调制特征（保基调、温和修正），让网络补足它欠缺的信息注入能力；
3. 若要零参数基线本身就有竞争力，应换"提光"语义的混合模式——这正是后续 `luminosity_screen_probe`（亮度蒙版 + 滤色）的出发点，实验证实滤色在同图对比中约 7/10 指标反超 T5。

## 5. 已知局限

- **无空间自适应**：同一 (base, blend) 组合全图同一修饰规则，没有"哪里该融合多少"的判断。
- **W3C ≠ PS**：与 Photoshop 的 Pegtop 实现在暗区行为有差异，主观经验不能完全平移。
- **灰度 VI 下优势不适用**：TNO 的 vi 本身是灰度，"VI 保色彩"的动机不成立（且层序偏好会翻转，见 §4.3）。
- **抽样仅 6 张、指标为均值**：样本量小，未做显著性检验，结论方向性参考；逐图计票（§4.2）部分缓解但不改变小样本性质。
- **尺寸对齐**：任何与 T5 输出同图算指标的脚本必须先对齐 16 倍数 resize（`load_pair_t5` 的存在原因），直接用原图尺寸会形状不匹配。
